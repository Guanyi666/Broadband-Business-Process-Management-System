## 一、项目简介

BBPMS 是面向宽带运营商的一体化业务管理系统，覆盖**客户开户 → 订单受理 → 审核 → 派单 → 装维施工 → 网络开通 → 售后维护**全生命周期。本次 2.0 升级在原有系统基础上，围绕"流程更完善、权限更安全、资源更透明"三个目标，分多轮迭代逐步落地。

**技术底座**：后端 Spring Boot + Java 21（模块化单体），前端 Vue 3 管理后台 + 装维移动端 H5，数据库 MySQL + Redis，Docker 一键编排部署。

## 三、本项目目前完成了哪些工作

### 1. 系统全面体检（ITERATION 0）

对现有系统做了一次彻底检查，产出三份专业审计报告：

- **架构审计**：梳理了全系统 26 张数据表的关系、订单/工单状态流转规则、派单评分规则等家底
- **后端审计**：逐一检查了 124 个接口，找出 12 处权限漏洞
- **前端审计**：盘点 50 个页面路由的权限控制情况

并在此基础上制定了 **16 项改进主题 + 13 轮迭代路线图**，后续所有工作都按这份路线图推进。

### 2. 核心流程与权限安全（ITERATION 1）

**① 订单驳回后可修改重提（流程闭环）**

- 原来：订单被审核驳回后直接作废，客户只能重新下一单，数据重复且体验差
- 现在：驳回的订单进入"已驳回"状态，客服可修改信息后重新提交，重新走审核流程，全程留痕

**② 补上权限漏洞（安全加固）**

- 查出 12 处接口缺少权限校验，已全部补齐——现在每个接口都有严格的角色权限控制，杜绝越权访问

**③ 数据权限细化（各部门只看自己的数据）**

- 原来：系统所有人能看到全部订单数据
- 现在：支持按部门隔离数据。部门调度员只看本部门的单，总部角色可看全部，管理员可看本部门及下属部门（树状递归）——真正做到"各司其职、数据隔离"

### 3. 地址与网络资源管理（ITERATION 2）

**① 建立网络资源台账（从无到有）**

- 把零散的自由文本地址，升级为**区域 → 小区 → 楼栋 → 单元 → 房间**四级结构化台账
- 新增 **OLT/PON/ONU 网络设备台账**（机房设备 → 分光端口 → 用户终端光猫），设备与房间可绑定
- 管理后台新增"资源管理"页面，管理员可维护小区、楼栋、设备等信息

**② 下单前资源核查（核心业务价值）**

客户下单时，输入安装地址即可**实时核查该地址的资源状况**，三种结果：

| 核查结果 | 含义 | 业务处理 |
|---|---|---|
| ✅ 可安装 | 该房间在资源台账内且未安装 | 正常下单，记录绑定关系 |
| ⚠️ 资源不足 | 该房间已安装，或无此房号 | 提示客服联系客户换地址 |
| ❌ 暂无覆盖 | 该小区/楼栋不在资源台账内 | 提示联系客服登记覆盖 |

核查结果自动写入订单，全程留痕，避免"单下了装不了"的返工。

## 四、当前系统已实现的功能清单

### 管理后台（Web 端，供客服/审核/调度/管理员使用）

| 功能模块 | 能力 |
|---|---|
| **登录认证** | 账号密码 + 图形验证码 + 加密传输，未登录/越权自动拦截 |
| **数据看板** | 订单总量/状态分布/派单时长等核心指标实时展示 |
| **客户管理** | 客户信息建档（姓名/电话/证件加密存储） |
| **订单管理** | 下单、审核（通过/驳回）、驳回后修改重提、取消、8 种状态全程跟踪、时间线留痕 |
| **工单与派单** | 派单（智能评分推荐 + 手动选择）、改派、装维进度跟踪 |
| **资源管理** | 小区/楼栋/单元/房间台账维护 + 网络设备台账（OLT/PON/ONU） |
| **下单资源核查** | 输入地址 → 自动核查可安装性（可装/不足/无覆盖） |
| **系统管理** | 用户/角色/部门/菜单管理，细粒度权限控制 |
| **中文化** | 全站界面已实现中文（原 20+ 英文页面已清理） |

### 装维移动端（H5，供上门装维人员使用）

| 功能模块 | 能力 |
|---|---|
| 施工任务 | 查看我的工单、上门施工、改派申请 |
| 考勤与请假 | 装维人员签到、请假登记（供派单时排除不可用人员） |
| 在线状态 | 人员在线状态同步（派单系统据此挑人） |

### 核心业务闭环已跑通（端到端实测验证）

> 建客户 → 下单 → 审核通过 → 自动/手动派单 → 生成工单 → 装维施工 → 开通 → 完成

以上全链路已通过自动化测试与真实页面操作双重验证，无阻塞问题。
