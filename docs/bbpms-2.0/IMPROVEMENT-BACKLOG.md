# BBPMS 2.0 差距分析与改进路线（ITERATION 0）

> 产出时间：2026-09-03 · 依据：ARCHITECTURE.md / BACKEND-AUDIT.md / FRONTEND-AUDIT.md

## 1. 当前业务流程（现状）

```
客户(admin 客服代录 customer) 
 → broadband_order 创建 CREATED
 → 订单审核 AUDIT_PASS/AUDIT_REJECT (审核员) → AUDITED / CANCELLED
 → 开始派单 START_DISPATCH (调度员) → WAIT_DISPATCH
 → 派单 DISPATCH_OK (调度/自动) → DISPATCHED
 → 生成 work_order PENDING → DISPATCHED
 → 装维接单 ACCEPTED → 施工 IN_PROGRESS（含 STALLED/REASSIGNING 分支）
 → 施工完成 COMPLETE → FINISHED（install_record 记录 ONU/SN/照片/签名）
 → 客户确认 CONFIRM → CLOSED（归档）
旁路：SLA 调度器（接单超时→AUTO_CANCELLED；停滞→STALLED→自动取消）
     消息通知（SMS/微信/站内，模板驱动）
     考勤/请假（装维端）
```

已实现链路的每一环都有页面/API/状态机/角色约束（见 ARCHITECTURE §3）。

## 3. 状态映射草稿（兼容性分析）

> 原则：**扩展现有枚举，新增状态向后兼容；旧数据不回迁（VARCHAR 存储天然兼容）**。

### 订单状态 ⇄ 2.0
| 现状 | 2.0 订单状态 | 手法 |
|---|---|---|
| CREATED | 待提交 / 待审核 | CREATED 释义扩展为"待提交→待审核"（加 DISPATCH 前资源核查步骤） |
| AUDITED | 审核通过 | 名称保留；AUDIT_REJECT 由"直入 CANCELLED"改为"REJECTED 可重提" |
| WAIT_DISPATCH | 待履约 | 中间插入资源核查已完成、预约已完成两个子状态位（可用 appointment 关联表达） |
| DISPATCHED | 履约中 | 语义宽展 |
| INSTALLING | 履约中 | 同上 |
| FINISHED | 已完成 | 保留 |
| CLOSED | 已归档 | 保留（终态） |
| CANCELLED | 已取消 | 保留（终态） |

新增枚举值（向后兼容，不删旧值）：REJECTED（审核驳回待重提）、RES_CHECKING（资源核查中）、APPOINTING（预约中）。

### 工单状态 ⇄ 2.0
| 现状 | 2.0 工单状态 | 手法 |
|---|---|---|
| PENDING | 待派单 | 保留 |
| DISPATCHED | 已派单 | 保留 |
| ACCEPTED | 已接单 | 保留 |
| IN_PROGRESS | 预约确认→前往现场→已到达→施工中 | **用 visit_stage 子字段表达**（staying 兼容主 status），避免破坏存量状态机 |
| STALLED / REASSIGNING | 异常 / 改派中 | 保留 |
| COMPLETED | 待验收→已完成 | COMPLETED 前增加"待验收"子阶段（验收动作挂 evaluation） |
| CANCELLED / AUTO_CANCELLED / FAILED | 已取消/自动取消/失败 | 保留（终态） |

### 网络业务状态（全新，ITERATION 6）
待开通 → 配置中 → 已开通 → 暂停 → 欠费 → 销户（新建 `broadband_account` 表承载，独立于订单状态）。

## 5. 推荐迭代路线（每轮主题/依赖/验收点）

> 遵循任务书：每轮一个主题、可演示、不堆砌。P0 三项先行。

```
ITERATION 0 (本轮)  系统审计 → 基线文档 4 份 + 本 backlog        [已交付]
ITERATION 1        核心状态机完善：P0-1 驳回重提 + P0-2 权限注解补齐 + P0-3 数据权限 DEPT 落地
                   验收：驳回订单可改重提；12 缺注解端点补全；非本部门调度员数据隔离
ITERATION 2        地址与网络资源管理（区域/小区/楼栋/单元/房间 + OLT/PON/ONU）
                   验收：订单创建时输地址→资源核查→可安装/资源不足/暂无覆盖
ITERATION 3        安装预约（时间段/改约/取消 + 派单前置）
                   验收：审核通过→选时间段→生成预约→预约状态机闭环
ITERATION 4        装维施工全过程（visit_stage 子阶段 + 测速/测试结果 + 客户验收）
                   验收：接单→前往→到达→施工→测速→待验收→验收完成，全程时间线可查
ITERATION 5        网络开通模拟（宽带账号/VLAN/ONU 绑定/激活/测速/审计）
                   验收：施工完成→模拟开通→成功/失败路径均可追踪
ITERATION 6        故障报修（复用 work_order 扩展 REPAIR + 故障等级/原因/诊断）
ITERATION 7        客户 360°（客户详情聚合全景）
ITERATION 8        SLA 2.0 + 运营数据中心
ITERATION 9        智能派单 2.0 + 智能运营中心
ITERATION 10       设备/材料生命周期 + 业务变更（移机/提速/停机/复机/过户/销户）
ITERATION 11       投诉管理 + 客户评价
ITERATION 12       客户侧 H5（安装进度时间线/报障/评价）
ITERATION 13       AI Agent（受控查询/分析/建议）
```

> 注：任务书建议 I5 设备材料先于开通，但按业务价值（开通是施工完成后的直接下一步、演示价值最高）与依赖（开通依赖施工记录，不依赖库存），调整为 I5=网络开通。设备/故障/投诉依需求弹性排期，不机械执行原 16 轮编号。
