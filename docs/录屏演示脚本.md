## 一、录制前只做一次的准备

### 1. 录制参数

- 输出格式：MP4。
- 分辨率：1920×1080。
- 浏览器缩放：100%，关闭书签栏、下载栏和无关插件提示。
- 开启麦克风降噪，关闭微信、QQ、系统通知和输入法悬浮窗。
- 文件名：`学号_姓名_演示录屏.mp4`。
- 整段连续录制，所有提交、派单、完工和评价都使用真实系统操作，不后期伪造成功画面。

### 2. 启动顺序

录制前先启动，确认成功后再打开录屏软件：

1. 启动 Docker Desktop。
2. 在项目根目录启动 MySQL 和 Redis：`docker compose up -d`。
3. 启动后端 `BbpmsApplication`，端口为 `8080`。
4. 为避免演示时 Mock BSS 随机失败，给后端增加启动参数：`--bbpms.install.bss.failure-rate=0`。
5. 分别启动三个前端：管理后台 `5173`、装维端 `9002`、客户端 `9003`。
6. 打开 `http://localhost:8080/actuator/health`，看到状态为 `UP` 后再录制。

### 2.1 装维端接口自检

当前源码已统一补齐后端校验需要的 `workOrderId`，并修正了照片、签名和完工请求格式，不需要再手工改代码。启动装维端后刷新一次页面；如果浏览器仍显示修改前的旧报错，按 `Ctrl+F5` 强制刷新。

## 四、遇到意外时怎么继续，不要慌

### 1. 新订单审核后没有立刻出现关联工单

口播：“自动派单采用异步事件执行，短暂延迟不会阻塞审核事务。”然后进入“派单工作台”，点击“刷新”。本片后续使用的是固定工单 `WODEMO20260204`，不受这个新订单影响。

### 2. 派单工作台找不到 `WODEMO20260002`

先点页面上的“刷新”。派单工作台只显示状态为“待派发”的工单，不支持在这里搜索全部工单；如果刷新后仍为空，说明固定演示数据缺失或已经被派发，应先恢复演示数据，不要临时改用状态不明的工单。

### 3. 派单工作台没有在线装维

不要开始正式录制。先确认装维人员在数据库中为在岗、Redis 已连接，并用装维端完成一次签到或位置上报。候选列表正常后重新开始。

### 4. 装维端“确认到达现场”为灰色

这是浏览器没有返回定位。录制前在地址栏左侧的网站权限中允许位置，刷新装维端；不要在正式录像中临时排查权限。

### 5. 三张照片选完仍不是 `3/3`

等待每张上传完成；失败的图片重新选择。必须看到 `3/3` 后再点下一步。

### 6. 提交完工提示 BSS 失败

说明后端没有使用准备阶段的参数 `--bbpms.install.bss.failure-rate=0`。停止试录，按参数重启后端并恢复演示数据，再重新录制；不要靠剪辑伪造成功。

### 7. 客户端找不到 `BBDEMO20260204`

确认登录的是 `customer1`，并在“我的订单 → 全部”中查找。如果固定工单刚完工，先下拉刷新。

## 五、严格 5 分钟压缩法

如果老师明确规定不能超过 5 分钟，主线不变，只做以下压缩：

1. 删除完整版 01:00～01:20 的资源台账独立浏览；创建订单时的“资源核查”已经证明该功能。
2. 菜单扫视压缩为 8 秒，但仍完整念出所有支撑模块，保证功能范围不漏。
3. 看板说明压缩为 20 秒，客户评价段压缩为 20 秒。
4. 装维五步操作控制在 87 秒：输入内容不变，三张图片一次多选。
5. 运营支撑不再逐页停留，只打开“操作日志”，用 8 秒口播 SLA、考勤、请假和审计能力。
6. 两段代码合并为 22 秒：先展示加权公式，再切到分布式锁；锁的口播压缩成一句：“派单通过 Redis 对订单和装维双重加锁，并配合幂等检查避免重复工单。”
7. 收尾控制在 10 秒。
