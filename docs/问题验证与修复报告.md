## 5. 风险提示

本次修改可能影响的功能及建议的后续测试范围：

1. **客户模块**（改动最大）：`page()` 从 SQL 分页改为内存过滤+重算 total，建议回归验证分页跳转/每页条数切换/搜索组合；明文接口新增日志记录（`OperationLog`"查看客户敏感信息"），确认审计链路无泄漏。客户密文统一后，**历史明文客户若通过 `upsert` 幂等逻辑会按"手机号密文"重新查重**，理论上已加密数据查重正常，但建议用真实手机号做一次重复新增测试。
2. **keep-alive 刷新**：`onActivated` 会在每次路由返回时触发数据请求，多页面同时切换可能带来轻微请求量上升；建议确认详情页跳转/弹窗关闭/标签页切换场景下无重复提交或加载闪烁。
3. **操作日志中文化**：`@OperationLog` 注解值变更影响新日志写入，历史数据已一次性更新；若外部系统（如 BI）依赖英文 action 值需同步适配。
4. **权限指令注册**：`v-hasPermi` 注册后，请假审批按钮对具备 `leave:approve-l*` 权限的角色（DISPATCHER/SUPER_ADMIN）将正常显示；请确认**其他页面**若此前依赖该指令未显示的元素，现在可能开始显示——建议全站巡检一遍按钮显隐是否符合权限预期。
5. **数据修复脚本**：`fix-data-issues.sql` 已幂等（按 ID/order_id 精确更新），可重复执行；但客户 PII 加密语句在脚本注释中说明需单独执行，**请勿对已加密的客户表重复执行明文加密**（会导致二次加密、无法解密）。
6. **地址回填**：仅回填了种子数据的 3 组地址；若后续发现其他乱码行，需人工确认正确地址后回填（0x3F 损坏不可逆，无法自动还原）。
