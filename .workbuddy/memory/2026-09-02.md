## 该项目核心结论（供后续会话复用，避免重复分析）

**架构**：模块化单体（1 个 Maven 模块 bbpms-app，13 个业务包），Java 21 + Spring Boot 3.2.5 + MyBatis-Plus 3.5.7 + Redis/Redisson + MySQL 8。原规划 11 微服务，落地为单体，跨模块用进程内事件总线（`ApplicationEventPublisher`）替代 MQ。

**安全模型（最关键、最反直觉）**：
- `SecurityConfig` 里 `.anyRequest().permitAll()`，过滤器链全放行
- 认证靠 `JwtAuthInterceptor`（查 Redis 会话 + 桥接 SecurityContext）
- 授权靠每个方法显式写 `@PreAuthorize`
- **后果：漏写 @PreAuthorize = 静默放行给所有登录用户**。这是系统性风险。

**已确认的主要问题**（报告第 14 节）：
1. `POST /api/dispatch/auto` 无 `@PreAuthorize`（`DispatchController.java:32-36`）—— 任意登录用户可触发派单，高危
2. 多个读接口无权限注解：`WorkOrderController:55/61/67/154`、`MessageTemplateController:33/37`、`SysMenuController:47`（/perms）、`WorkOrderTimelineController:31`
3. `@Cacheable/@CacheEvict`（`SysUserServiceImpl:62/84/158`）全失效——全局无 `@EnableCaching`、无 CacheManager
4. `wo_sla_policy` 表建了但 SLA 调度器硬编码 30min/4h/24h 不读它
5. 数据权限只实现 SELF，DEPT/CUSTOM 未实现
6. `InstallServiceImpl` 中文乱码（UTF-8 被按 GBK 解码）
7. 两个 Snowflake 生成器同为 worker=1/dc=1 且是独立实例（order 那个标了 @Primary）

**状态机**：`OrderStateMachine` 8 状态、`WorkOrderStateMachine` 10 状态，转移表里硬编码角色码 1~6（魔法数字）。

**派单算法**：`DispatchScoringService` 四维加权 —— 距离 40%(Haversine) / 负载 25% / 技能 20% / 评分 15%；候选来自 Redis ZSET `installers:active` 并排除请假；订单级锁 `lock:dispatch-order:{orderId}` 在首次 SELECT 前获取（SA-P2-004 修复）。

**"文档有、代码没有"的陷阱**（勿信文档，以代码为准）：wo_sla_policy 未接入、DEPT 数据权限未实现、Dashboard 缺失（SA-P2-005）、缓存注解失效。

**历史修复记录**见 `docs/SPRINT_A_ISSUES.md`（SA-P0-001~SA-P3-002、SB-N1~N4），改代码前必读，避免复发。

发现的真 bug（仅静态编译不可见）：
1. **后端 ONLY_FULL_GROUP_BY 不兼容** — 原 com.bbpms.dashboard 包的 SQL（GROUP BY DATE(create_time) SELECT create_time）触犯 MySQL 8 默认 sql_mode，导致 dashboard 历史接口恒 500。所谓"幽灵接口"其实是"恒 500 的接口"。修复：Mapper/Service/Controller/VO 重写为设计契约 3 接口 (overview/trend/dispatch-duration)，全部 GROUP BY 用 SELECT 同表达式。
2. **前端 Vue 模板嵌套 Ref 未解包** — useDashboard 模块的 loading/error 嵌在 plain 对象中传给 BBPMSKpiCard/BBPMSPanel 的 prop，Vue 不会自动解包，结果永远是 Ref 对象 → loading 恒真、面板永远 加载失败。vue-tsc 未捕获。修复 15 处模板补 .value。
3. **git 工作树被外部进程反复篡改** — 在本会话期间至少观察到：admin-web/src/api/dashboard.ts 被改回旧版、useDashboard.ts 被替换为中间版本、types/dashboard.ts 整个文件消失、src/views/dashboard/index.vue 在 final 与 intermediate 间反复。reflog 显示会话开始时发生过 `git reset --mixed origin/main`（保留工作树但 HEAD 移回 619dc90）。对策：先 `git reset --mixed origin/main`（与我无关的外部操作），把工作树当成权威重新对照设计契约修复，每次修复后立即 commit 锁定（本次产出 commit `9b8aca2`、`ceae632`）。
